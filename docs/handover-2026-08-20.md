## 3. ⚠ Seven new defects — none fixed

The programme was a **verification** role and deliberately applied no fixes (audit #4's own lesson).
Every one has a reproducer and a filed block in `docs/todo.md`.

| id | impact | fix cost |
|---|---|---|
| **`[INVOKEINHERIT-2026-08-20]`** | **Worst one.** `Ubel::WalkFunctions` never climbs `SuperStruct`, so `UE5_FindFunctionByName` can only resolve a function a class *declares*. `AActor`'s **140** functions are unreachable on every subclass; 11 of 42 live objects can invoke nothing at all. It also silently breaks the shipped **Debug Camera** on any game with a derived CheatManager (`UE5_SetDebugCamera` resolves `ToggleDebugCamera` off the live CheatManager's class). | S — but ⚠ **do NOT make `WalkFunctions` inherit**: it is also what LISTS a class's functions, and the UI attributes each to its declaring class. Fix the **resolvers**. Adding a `func_addr` input to `invoke_function` independently removes the dependency. |
| **`[FREEZEINJECT-CRLF-2026-08-20]`** | "Inject Freeze Helper" reports `wrote 58345, stream has 57208` and the user concludes the Freeze feature is broken. **The write actually succeeds.** | **S, cheapest.** The helper is 58,345 bytes with **1,137 CRLF** endings and 58,345 − 1,137 = 57,208 exactly; CE stores it LF-normalised and the check compares a CRLF byte count to an LF stream. Compare the normalised length, or compare content. ⚠ Do not "fix" it by writing LF without checking what else reads that file — the stored content is already correct. |
| **`[FREEZEUNTICK-2026-08-20]`** | A Freeze bail-out that applies nothing leaves the record **`Active=true`** — the user is told a cheat is running when none is. Confirmed on **both** the helper-missing and DLL-not-injected paths. | S~M. The generator *does* emit `if memrec then memrec.Active = false end`, and the same assignment works from outside, so the in-ENABLE one does not survive. **Leading hypothesis, not yet measured:** CE finalises activation after ENABLE and overwrites it ⇒ use the **deferred** untick this repo already has for the momentary-action shape. Confirm with a minimal record whose ENABLE does nothing but `memrec.Active=false`. |
| **`[CDOSCOPE-2026-08-20]`** | `(CDO default)` is decided on an **exact** `ClassPrivate` match while Force/Freeze on the same row scope **derived** — a row reads "nothing live" and the action then hits 2 instances. | S~M. Same exact-vs-derived split as `FREEZESCOPE` / audit #5 `A6`, one layer up; worth fixing together. |
| **`[SNAPINTERVAL-2026-08-20]`** | A below-minimum auto-snapshot Interval committed by **clicking away** (not Tab) blanks the field and shows a raw `System.InvalidCastException`, greying out Retention and Count. Tab-commit clamps correctly. | S — apply the same clamp on the lost-focus path. |
| **`[STAGELOCK-2026-08-20]`** | Deploying a proxy over a **mapped** DLL (a running game) throws `UnauthorizedAccessException`, which is **not an `IOException`** — so `DeployAsync`'s `catch (IOException …)` "File locked (game running?)" filter misses it and the user gets a raw *"Access to the path is denied."* that does not even name the path. Measured at the OS level: the old `File.Copy` gave `ERROR_SHARING_VIOLATION (32)`, the new staged `File.Move` gives `ERROR_ACCESS_DENIED (5)`, because a replacing rename must first *delete* a target that carries an image section. | S. Widen the filter to the exception the staged path actually throws. ⚠ The AC11 row's own premise ("the rename now raises the sharing violation the direct copy used to") is **wrong** — fix the row too. |
| **`[ORPHANCANCEL-2026-08-20]`** | LOW. An interrupted leftover-proxy cleanup under-reports: the log shows **three** `Recycled leftover proxy` lines while the tally counts two. Files were recycled that the summary does not admit to. | S. |

**Suggested order:** `FREEZEINJECT-CRLF` (trivial, and it is what makes Freeze *look* broken) →

## 5. ⚠ Things that will mislead you

* **A game process that exists is not a game that booted.** Satisfactory's shipping exe cannot be
  launched directly (`Failed to open descriptor file …FactoryGameSteam.uproject`); it needs
  **`steam.exe -applaunch 526870`**. Injection, the pipe and the scan all succeeded against the dead
  engine and produced *coherent* numbers — `GObjects=0x0`, `ExtraScanGObjects: No valid FUObjectArray
  found (763 candidates tested)`. Re-run properly: **all four globals, 137,425 objects**, with
  `gobjects` at the very address the failed run had rejected as empty. Tell: a symbol that **resolves**
  with an **empty** array, and `object_count == 0`. Full write-up in `working-lessons.md` §3.w.
* **`proxy_refresh.py` false STALE** — see §1.
* **Log windows.** Four variants of one mistake were hit in a single day: line-count slicing across
  several growing files, a one-second timestamp watermark between events milliseconds apart, a counter
  read outside the timed window, and a byte offset recorded before a process start that **rotates** the
  log. Use before/after **counts**. `working-lessons.md` §1 has the table.
* **`find_instances` without `exact_match` is a NAME SUBSTRING match** — "the first live instance of
  `Actor`" was a `UActorSequence`, and a wrong-type invoke left queued can drain later.
* **`invoke_function` cannot call an INHERITED function** (`[INVOKEINHERIT]`) — pick an instance whose
  class *declares* the function or your rig fails for the wrong reason.
* **`working-lessons.md` §4.4's Everspace 2 evidence is RETIRED.** That KismetMathLibrary no-op was
  the wrong vtable slot, not BlueprintFastCall: with a correct hook `Add_IntInt(3,4)` returns **7**.
  A KismetMathLibrary failure should now be suspected of being a bad slot first.
* **PE vtable slots are per-BUILD, found by pattern:** `0x268` DumperTest 5.4 · `0x260` Lushfoil 5.6 ·
  `0x278` EVERSPACE 2. Do not "fix" the version table.

## 6. Driving Cheat Engine (this is what unlocked §3's three defects)

* `C:\Program Files\Cheat Engine\Cheat Engine.exe` is a shim; the real process is
  **`cheatengine-x86_64-SSE4-AVX2.exe`**.
* The **AOBMaker plugin auto-loads** from `plugins\AOBMaker_CEPlugin.dll`. Seconds after CE starts the
  UI toolbar flips **AOBMaker Offline → Connected**, and *that* is what enables the per-row **Freeze**
  button (`PropertySearchPanel.axaml:285`, bound to `IsAobMakerAvailable`). With CE closed the button
  is present but dead.
* Attach: process icon → pick the game → **Open** → answer **Yes** to *"Keep the current address
  list?"*, or you lose the record you just pushed. ⚠ **Read the title bar before ticking** — the
  process list reorders between openings and one attach landed on `UE5DumpUI.exe`.
* ⚠ **Read `memrec.Active` from CE's Lua Engine, never from the checkbox icon.** Measured this
  session: **red ✗ = Active**, empty box = inactive.
  ```lua
  local r = getAddressList().getMemoryRecord(0) print('Active=' .. tostring(r.Active))
  ```
* Emitted scripts are silent by default; `UE5_DEBUG=1` in the Lua Engine turns on the
  `[Freeze] Started/Stopped` lines — the CE-Lua hygiene contract, confirmed live.
